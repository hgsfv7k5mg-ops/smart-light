# Smart Light 使用与验证手册

这是一份按阶段组织的上手手册。假设你已经装好 ESP-IDF、能把固件烧进板子，
但还不熟悉这套工程，那么照着章节顺序走就可以了 —— 每一步都写明了**能看到什么**，
大部分步骤不需要 WiFi、云或手机。

> 建议按阶段推进：**每个阶段都有明确的通过标准**，确认通过后再进入下一阶段，
> 这样一旦卡住，排查范围会小很多。如果暂时过不了，先按该章节末尾的提示看一看，
> 多半是接线或配置项的小问题，不用着急。
>
> 阶段 ① 完全不需要 WiFi、不需要云、也不需要手机。

---

## 路线图

| 阶段 | 需要什么 | 通过标志 |
|---|---|---|
| ① 本地功能 | 板子 + 串口线 | OLED 有画面、灯随环境光变、COLOR 能变色、ALARM TEST 响铃 |
| ② 联网 | 路由器（或手机配网） | `STATUS` 里 `WiFi=已连接`、`SNTP=已校时`、北京时间正确 |
| ③ 云端 | 上位机 Broker（`host/`） | 网页大屏出现温度/光照曲线，点按钮能改灯，能设定时开关灯与闹钟 |
| ④ 手机配网 | Android/iOS + ESP BLE Prov App | 不写死 WiFi 也能联网（可选，阶段②用了方式 A 的话可以晚点再看） |
| ⑤ OTA 升级 | 上位机 HTTP 服务 | 发布新固件后设备自动下载、重启、版本号变化（可选） |

其中 ② 有两种方式：**建议先用方式 A 把联网跑通**，再回头玩配网（第五章），
排查会简单很多。

## 第一章 本地功能验证（不需要 WiFi / 云 / 手机）

### 1.1 编译、烧录、开串口

**VS Code + ESP-IDF 插件（推荐）**

1. 打开工程文件夹
2. 底部状态栏确认目标芯片是 `esp32s3`、端口选好（如 `COM3`）
3. 点 ⚙️(Build) → ⚡(Flash) → 🖥️(Monitor)，或直接用 `Ctrl+E` 然后依次按 `B` `F` `M`
4. 监视器波特率 **115200**

**命令行**（在 ESP-IDF 终端里）

```
idf.py -p COM3 flash monitor
```
退出监视器：`Ctrl+]`

### 1.2 上电后先看"配置体检"

设备启动会打印这样一块，可以对照着看当前缺什么：

```
========== 配置体检 ==========
  WiFi 凭据  : 未填 -> 首次启动自动进入蓝牙配网
  配网 POP   : abcd1234（手机 App 连接时要填）
  MQTT 云端  : mqtt://192.168.1.100:1883（上报周期 5s）
  常用命令   : HELP / STATUS / CLOUD STATUS / WIFI STATUS / PROV
==============================
```

这里可以留意一点：**云端配置缺失时 MQTT 会自动跳过，其它功能不受影响**，
所以第一阶段可以先不看联网部分。

紧接着是命令帮助和串口控制台：

```
Smart Light 串口控制台已就绪
输入 HELP 查看全部命令
```

> 串口输入命令后按回车即可。VS Code 的 Monitor 里直接打字就行（没有回显是正常的）。

### 1.3 逐项验证清单

按顺序做，每步都有可以观察到的现象：

| # | 操作 | 期望现象 | 未通过时可以看看 |
|---|---|---|---|
| 1 | 上电 | OLED 显示主界面（温度/光照/模式），灯亮起 | OLED 接线 SCL=GPIO7 SDA=GPIO8；VCC 3.3V |
| 2 | `PAGE 1` / `PAGE 2` / `PAGE 3` | 主界面 / 闹钟定时器 / 网络状态 三页切换 | — |
| 3 | `AUTO` | 进入自动模式，颜色由温度决定、亮度由环境光决定 | — |
| 4 | 用手**完全遮住**光敏电阻 | 环境光百分比下降 → **灯变亮** | ADC 引脚 GPIO4；`STATUS` 里看 `环境光` 是否变化 |
| 5 | 用手机手电筒照光敏 | 环境光上升 → **灯变暗**（最低保留 10% 亮度） | 同上 |
| 6 | 手指捏住 DS18B20 芯片 | `STATUS` 里温度上升，灯颜色朝红色方向变 | DS18B20 在 GPIO9，需要 4.7 kΩ 上拉到 3.3 V；显示 `--` 或 0 时可以敲 `TEMP` 看诊断，详见第六章 |
| 7 | `COLOR 255,0,0` | 灯变纯红（自动切到手动模式） | 共阳极接法，RGB 引脚 18/16/17 |
| 8 | `COLOR 0,0,255` → `COLOR 0,255,0` | 蓝、绿依次切换 | — |
| 9 | `BUZZ ON` → `BUZZ OFF` | 蜂鸣器响 / 停 | GPIO6 |
| 10 | `ALARM TEST` | **红灯闪烁 + 蜂鸣器鸣响，持续 10 秒**后恢复 | — |
| 11 | `OFF` → `AUTO` | 灯灭 → 灯恢复 | — |
| 12 | `STATUS` | 打印模式/颜色/温度/光照/WiFi/SNTP/云端/时间/闹钟列表 | — |

### 1.4 温度 → 颜色对照（验证温度变色用）

| 温度 | 显示颜色 | RGB |
|---|---|---|
| ≤ -10℃ | 纯蓝 | 0,0,255 |
| -10 → 15℃ | 蓝 → 青绿渐变 | 0, g↑, 255 |
| 15℃ | 青绿 | 0,255,255 |
| 15 → 30℃ | 青绿 → 纯绿（蓝分量退掉） | 0,255,b↓ |
| 30℃ | 纯绿 | 0,255,0 |
| 30 → 45℃ | 绿 → 红渐变 | r↑, g↓, 0 |
| ≥ 45℃ | 纯红 | 255,0,0 |

室温约 25℃ → 应看到**黄绿色**。用手捏 DS18B20 升到 33~35℃ 就能看到明显偏红。

### 1.5 自动调光公式

```
亮度系数 = 1 - 环境光百分比/100      （钳位在 0.10 ~ 1.00）
实际输出 = 温度决定的颜色 × 亮度系数
```
所以：环境越暗 → 系数越接近 1 → 灯越亮；环境全亮 → 系数 0.1 → 只剩 10% 亮度（不会全灭）。

### 1.6 一个值得留意的行为约定

**没有联网校时（SNTP）时，闹钟和定时器不会触发** —— 代码会在时间同步之后才开始检查
（`tm_year > 100`），这是有意的设计。

- 想先看看响铃效果 → 用 `ALARM TEST`（不需要时间）
- 想验证"到点真的会响" → 可以先完成阶段②联网校时，再回来测这一步

## 第二章 联网（两种选一种）

### 2.1 方式 A：把 WiFi 写进固件（首次推荐）

```
idf.py menuconfig
  → Smart Light 配置
    → WiFi
      → 默认 WiFi 名称   : 填可用的 2.4GHz SSID
      → 默认 WiFi 密码   : 填密码
```
保存退出后重新 `Build → Flash → Monitor`。

> 提示：ESP32-S3 只支持 2.4 GHz 频段，选 SSID 时留意一下，5 GHz 的网络是连不上的。

通过标准：串口出现
```
已连接 WiFi: <你的SSID>, IP: 192.168.x.x
校时成功
```
再用 `STATUS` 确认 `SNTP=已校时`、北京时间与实际一致（+8 区）。

### 2.2 方式 B：手机 BLE 蓝牙配网

完整步骤见 **第五章**。建议先用方式 A 跑通联网，再回来尝试配网，这样排查会简单很多。

### 2.3 联网后能做什么

| 命令 | 作用 |
|---|---|
| `WIFI STATUS` | 看当前 SSID / IP |
| `WIFI RESET` | 清除已存凭据，重启后重新配网 |
| `PROV` | 随时手动开启蓝牙配网 |

## 第三章 云端大屏：灯控 / 定时 / 闹钟

大屏地址 <http://localhost:8083>（先双击 `host\start-broker.cmd`）。
右上角的「模拟设备」不用硬件也能把这一章完整点一遍。

### 3.1 灯控

| 操作 | 期望现象 |
|---|---|
| 点「自动」 | 模式变 AUTO，卡片「工作模式」显示"自动" |
| 选颜色 → 点「发送」 | 手机/板子上的灯变色并切到手动模式，色块同步更新 |
| 点「关灯」 | 灯灭，模式显示"关闭" |

设备每 5 秒上报一条遥测，曲线持续滚动；鼠标移到曲线上能看到该点的时间与数值。

### 3.2 定时开关灯

1. 选开灯 `22:00`、关灯 `06:00`（关灯早于开灯 → 自动按**跨天**处理）；
2. 星期不选 = 每天，也可以只勾工作日；
3. 点「启用定时」。

通过标准：面板下方显示"运行中 · 22:00 - 06:00"，串口打印

```
alarm_mgr: 定时器已设置: 22:00 - 06:00 (跨天)
```

之后设备到点会在 **AUTO / OFF** 之间自动切换模式。想停 → 点「关闭定时」。

### 3.3 闹钟

1. 选时间 `07:30`、重复方式（重复 / 仅响一次），重复时可勾星期；
2. 点「添加闹钟」——列表最多 3 条，每条的「删除」按槽位生效；
3. 想立刻确认蜂鸣器与红灯 → 点「响铃测试」（响 10 秒，**不需要校时**）。

通过标准：串口出现

```
cloud_mqtt: 收到控制 #1: {"cmd":"alarm","action":"add","hour":7,"minute":30,"repeat":"daily","week":[1,3,5]}
alarm_mgr: 闹钟 1 已添加: 07:30 重复 1,3,5
```

到点后设备**红灯闪烁 + 蜂鸣器鸣响 10 秒**，OLED 第二页也能看到闹钟条目。

### 3.4 两端改配置保持一致

定时与闹钟既能在大屏改，也能在串口改（`ALARM ADD` / `TIMER ON`）。
设备每次改完都会主动补发一条遥测，大屏收到就刷新列表，
所以两边看到的始终是同一份配置，不用刷新页面。

### 3.5 报文（用 mqttx 手测时看这里）

| 动作 | 报文（发往 `light/<id>/set`） |
|---|---|
| 添加闹钟 | `{"cmd":"alarm","action":"add","hour":7,"minute":30,"repeat":"daily","week":[1,3,5]}` |
| 删除闹钟 | `{"cmd":"alarm","action":"del","slot":1}` |
| 清空闹钟 | `{"cmd":"alarm","action":"clear"}` |
| 响铃测试 | `{"cmd":"alarm","action":"test"}` |
| 设置定时 | `{"cmd":"timer","action":"set","hour_on":22,"minute_on":0,"hour_off":6,"minute_off":0,"week":[1,2,3,4,5]}` |
| 关闭定时 | `{"cmd":"timer","action":"off"}` |

`week` 里 **1 = 周一 … 7 = 周日**，空数组 = 每天；`repeat` 省略按 `daily` 处理。

## 第四章 OTA 远程升级

本工程把固件托管在**上位机自带的 HTTP 服务**上，不需要任何云平台控制台。

### 4.1 准备固件

要看出"确实升上去了"，需要先准备一份与新固件版本号不同的旧固件：

```powershell
# ① 把当前编译产物备份为旧版本（release\ 已在 .gitignore 中，不会入库）
copy build\smart_light.bin release\smart_light_v1.0.0.bin

# ② 改版本号：根目录 CMakeLists.txt 里的 set(PROJECT_VER "1.1.0")，重新编译
idf.py build

# ③ 把新固件发布到服务器的 OTA 目录
host\push-firmware.cmd
```

> 如果想做"升级前 / 升级后"的对比，可以先把第 ① 步备份的旧固件烧进板子
> （只写 app 分区即可），再触发 OTA。这里不太建议用 `idf.py flash` 烧旧版本 ——
> 它会按当前源码重新编译，升级前后就看不出版本差了。

### 4.2 确认服务器在跑

```
启动 host\start-broker.cmd
浏览器打开 http://localhost:8083
```

### 4.3 触发升级（三种方式任选）

| 方式 | 操作 |
|---|---|
| 串口 | 敲 `OTA`（用 menuconfig 里的默认地址），或 `OTA http://192.168.1.100:8083/ota/smart_light.bin` |
| 网页大屏 | 打开 <http://localhost:8083> →「OTA 固件升级」面板 → 选中固件 → 推送到设备 |
| MQTT | 向 `light/<id>/set` 发 `{"cmd":"ota","url":"http://..."}` |

### 4.4 通过标准

串口应依次出现：

```
smart_light: OTA 就绪  当前固件 v1.0.0  运行分区 ota_0
cloud_ota: ========== OTA 升级开始 ==========
cloud_ota:   当前版本  : 1.0.0     运行分区: ota_0
cloud_ota:   服务器固件: smart_light  v1.1.0  编译于 ...
cloud_ota:   下载中  10%   (...)
cloud_ota:   ✔ OTA 成功：新固件已写入备用分区，重启后生效
cloud_ota:   5 秒后自动重启进入新固件…
      ↓ 自动重启
smart_light: OTA 就绪  当前固件 v1.1.0  运行分区 ota_1
```

**看到「ota_0 → ota_1」与「v1.0.0 → v1.1.0」，OTA 这一步就算通过了。**

### 4.5 失败保护（不会变砖）

升级过程做了保护，任何一步出问题设备都会继续跑原来的固件：

| 失败环节 | 设备行为 |
|---|---|
| 服务器没开 / URL 写错 | 报错退出，**不切换分区**，继续跑旧固件 |
| 下载中途断开 | `下载中断`，不切换分区 |
| 拉到别的项目的固件 | 打印 `警告: 固件名不是 smart_light`，校验不通过则拒绝写入 |
| 新固件启动后崩溃 | Bootloader 自动回滚到原分区 |

> 一次 OTA 大约需要 1~3 分钟，取决于固件大小与网络状况，升级期间请保持供电。

## 第五章 手机 BLE 配网（完整步骤）

配网涉及蓝牙广播、手机 App 和 NVS 里保存的凭据三处状态，第一次接触时可能会觉得环节有点多。
建议先按第二章的**方式 A 跑通联网**，再回来看这一章，排查起来会轻松很多。

### 5.1 安装 App（请认准 ESP BLE Prov）

推荐使用 **ESP BLE Prov（ESP-IDF Provisioning）**。

- **Android**：应用商店搜 `ESP BLE Prov`；或到
  <https://github.com/espressif/esp-idf-provisioning-android/releases> 下载 `.apk`
- **iOS**：App Store 搜 `ESP BLE Prov`

> 选 App 时可以留意一下：本工程用的是 `wifi_prov_scheme_ble`
> （protocomm BLE / GATT server），与 EspBlufi 所用的 BluFi 协议不是同一套，
> 用 EspBlufi 会扫不到设备。

> Android 6.0 及以上版本还需要开启定位权限和定位开关，这是系统对蓝牙扫描的要求。

### 5.2 让设备进入配网模式（三种触发方式，任一即可）

| 方式 | 操作 |
|---|---|
| 自动 | menuconfig 里 WiFi 为空 + NVS 没有凭据 → 上电自动进配网 |
| 串口 | 敲 `PROV` |
| 重置 | 敲 `WIFI RESET`，3 秒后重启并自动进配网 |

串口会打印：

```
========== BLE 配网已开启 ==========
  设备名    : PROV_LIGHT_A4B2
  校验码POP : abcd1234
  手机 App  : ESP BLE Prov（ESP-IDF Provisioning）
  操作      : 打开 App → 扫描（设备名以 PROV_ 开头）→
              输入 POP → 选择目标 WiFi 并填密码 → 下发
  下发成功后设备会自动重启并用新凭据联网
====================================
```

### 5.3 手机端操作

1. 打开 **ESP BLE Prov** → 选 **Provision New Device** → 它会开始扫描
2. 列表里找 `PROV_LIGHT_XXXX`（设备名前缀为 `PROV_`）
   - 列表里没有的话可以先下拉刷新一次；仍然没有时，常见原因是 App 选错了（见 5.1），
     或者设备已经连上网、当前没有开广播（可以对照 5.2 的三种触发方式看一下）
3. 点你的设备 → 填入 **Proof of possession / POP**：`abcd1234`
4. 填写 WiFi：
   - SSID：选 2.4GHz 的网络（ESP32 不支持 5GHz）
   - 密码：WiFi 密码
5. 点 **Provision** 发送
6. 串口看到 `配网成功，已连上 AP` → 设备自动重启 → 用新凭据联网

### 5.4 成功标志

串口：
```
I (xxx) net_prov: 收到 WiFi 凭据: SSID=MyHome
I (xxx) net_prov: 配网成功，已连上 AP
I (xxx) net_prov: 配网流程结束，正在重启以应用新配置
```
设备会**自动重启**，重启后用新凭据连接 WiFi，凭据已存进 NVS，**以后上电不再需要配网**。

配网没成功时通常会看到：
```
凭据校验失败: 密码错误，将重新开始配网
```
这时可以再确认一次密码，或者换一个 2.4 GHz 网络试试
（部分仅支持 5 GHz、或需要企业级认证的网络暂时用不了）。

## 第六章 温度读数异常排查（DS18B20）

先敲 `TEMP`，一条命令输出全部诊断信息：

```
========== DS18B20 诊断 ==========
  设备状态: 地址 0x28FF640E1F3C4A5B | 成功 12 次 失败 0 次 | 最近: 正常
  转换结果: 26.50 C
  Scratchpad: 8A 01 4B 46 7F FF 0C 10 4E
  原始值  : 394 -> 24.62 C （1360 = 85.0C 上电默认值）
  分辨率  : 配置寄存器 0x7F（0x7F = 12bit）
==================================
```

| 现象 | 含义 | 处理 |
|---|---|---|
| `总线上未发现任何 1-Wire 设备` | 重试 3 次都收不到 presence 脉冲 | 电气层问题：查接线、上拉、供电 |
| `最近: 读到上电默认值 85℃` | 芯片有响应，但转换未完成 | 见 6.1 |
| `最近: CRC 校验失败` | 时序受干扰 | 缩短线材、确认 4.7 kΩ 上拉、远离 OLED 与电源 |
| 日志出现 `rmt: user buffer too small` | 总线有毛刺，符号被截断 | 见 6.3 |
| `成功 N 次 失败 0 次` | 工作正常 | —— |

### 6.1 读数一直为 0 的原因

DS18B20 上电时温度寄存器默认为 `0x0550`，即 **85℃**。驱动会识别该组合并返回
`ESP_ERR_INVALID_STATE`，而不是把 85 当作真实温度上报；若上层将该返回值视作读取失败、
保留变量初值，界面就会长期停在 0.0℃。

驱动的处理：读到上电默认值时自动重新转换（最多 3 次）。若仍反复读到 85℃，通常是：

- **寄生供电**：模块 VDD 悬空、只靠 DQ 取电，转换瞬间电流不足 → 把 VDD 接到 3.3 V 试试；
- **芯片兼容性**：部分兼容芯片的上电与转换时序和手册不一致 → 可以换一颗符合规范的 DS18B20 对比一下。

### 6.2 接线要求

1. VCC → **3.3 V**（DS18B20 支持 3.0~5.5 V），GND → 与 ESP32 **共地**；
2. DQ → **GPIO9**，DQ 与 3.3 V 之间接 **4.7 kΩ 上拉**（多数模块已自带）；
3. 线材短于 1 m，远离 OLED 与电源模块；
4. 内部上拉已默认开启，外部上拉缺失或虚焊时仍能为总线提供确定电平。

### 6.3 `rmt: user buffer too small` 的成因

RMT 后端做总线复位时只接收 **2 个 RMT 符号**（驱动内固定）。正常时序为主机拉低 →
主机释放 → 设备应答 → 设备释放，恰好 2 个符号；总线上任何毛刺都会使符号数超标而被截断，
presence 检测随即失败并报"未发现设备"——看似未接传感器，实为电平不干净。

确认接线无误后仍复现时，可切换 1-Wire 后端：

```c
/* components/board_config/include/board_config.h */
#define BOARD_ONEWIRE_BACKEND       2     /* 1 = RMT（默认），2 = UART */
#define BOARD_ONEWIRE_UART_PORT     UART_NUM_1
```

UART 后端以波特率模拟 1-Wire 时序，由 UART 硬件完成采样，抗毛刺特性与 RMT 不同。
引脚无需改动（TX/RX 复用 GPIO9），重新编译烧录即可。

## 第七章 排障速查表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| OLED 全黑 | I2C 线序 / 地址 | 检查 SCL=GPIO7 SDA=GPIO8；串口看有无 `oled_ui` 报错 |
| 温度一直显示 0 或 -- | 读到 85℃ 上电值 / 没上拉 | 敲 `TEMP` 看诊断，按**第六章**处理 |
| 灯颜色不对 / 偏暗 | 共阳极接法 | 确认模块是共阳极，代码按低电平点亮实现 |
| 光照百分比不动 | ADC 引脚错 | GPIO4；光敏 AO 输出 0~3.3V |
| 串口敲命令没反应 | 没按回车 / 端口被占用 | 命令需要以回车结束；确认只开了一个串口监视器 |
| WiFi 连不上 | 5GHz / 密码不对 | 换成 2.4 GHz 网络；或用 `WIFI RESET` 后重新配一次 |
| 一直重连直到停 | 超过 10 次自动重连上限 | 修好网络后敲 `REBOOT`，或 `PROV` 重配 |
| 闹钟不响 | 时间没同步 | 先联网校时；或先用 `ALARM TEST` 验证响铃 |
| 云端一直不在线 | 服务器没开、或设备与电脑不在同一网段 | 敲 `CLOUD STATUS` 看状态；确认 `host\start-broker.cmd` 在运行 |
| 编译报错说找不到组件 | `managed_components` 被清了 | 重新 `idf.py build`，联网自动下载 |
