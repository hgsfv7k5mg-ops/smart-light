# Smart Light 上位机使用说明

提供 **MQTT Broker + 实时网页大屏 + OTA 固件分发**，无需 Docker、WSL 或云账号。

设备端接入层为通用 MQTT，Broker 可整体替换为 EMQX / Mosquitto / ThingsBoard，
切换平台只改配置、不改业务代码。本目录用 Node.js `aedes` 提供一套开箱可用的实现，
安装依赖后双击 `start-broker.cmd` 即可运行。

---

## 一、架构

```
ESP32-S3 ──MQTT/TCP :1883──┐
                            ├──  broker.js  ──┬── MQTT Broker（aedes，消息路由）
浏览器  ──WebSocket :8083──┘                 ├── HTTP 静态服务（大屏页面 / mqtt.min.js）
                                             ├── /api/info   运行状态与最新遥测
                                             ├── /api/ota    可用固件列表
                                             └── /ota/*.bin  固件下载（给设备 OTA 用）
```

| 端口 | 协议 | 用途 |
|------|------|------|
| 1883 | MQTT over TCP | ESP32 上报遥测、接收控制指令 |
| 8083 | HTTP / WebSocket | 大屏页面、MQTT over WS、状态 API、固件分发 |

---

## 二、目录内容

```
host/
├── broker.js            # MQTT Broker + HTTP 服务（单文件，无框架）
├── dashboard.html       # 实时大屏（纯前端，无构建步骤）
├── package.json         # 依赖声明：aedes / ws / mqtt

├── push-firmware.cmd    # 把 ../build/smart_light.bin 发布到 ota/
├── ota/                 # 固件目录（*.bin）
└── 使用说明.md
```

## 三、快速开始（无需硬件）

```cmd
cd host
npm install            :: 首次需要，之后可跳过
```

然后**双击 `start-broker.cmd`**，浏览器打开 <http://localhost:8083>。
若 Broker 已经在运行，脚本会跳过启动、直接打开大屏，不会报端口占用。

> **换台设备看大屏**：把地址里的 `localhost` 换成电脑的局域网 IP 即可，即
> `http://192.168.1.100:8083`（手机、平板在同一网段就能访问）。

页面右上角有个「模拟设备」按钮，点一下就会用假数据跑起来，
可以先用它确认「大屏 ← Broker ← MQTT」这条链路是通的，再接真实硬件。
模拟设备同样响应灯控、定时与闹钟指令，没有板子也能把「定时开关灯 / 闹钟」面板点一遍。

## 四、接真实 ESP32

### 4.1 前提：设备与电脑需要在同一网段

```
电脑  : 192.168.1.100   （WLAN）
ESP32 : 192.168.1.x     （同一个路由器下）
```

不同网段时 MQTT 包到不了电脑，三种解决办法任选其一：

| 方案 | 做法 | 说明 |
|------|------|------|
| A. 设备连电脑所在路由器 | 设备配网时选同一个 WiFi | 最稳定 |
| B. 电脑连设备所在热点 | 把电脑 WiFi 切换到同一热点 | 电脑 IP 会变，需同步改 `CONFIG_CLOUD_MQTT_URI` |
| C. 用公共 Broker | 填 `mqtt://broker.emqx.io:1883` | 不需要同网段，但数据与他人共用服务器 |

改完 IP 后记得同步修改固件里的 Broker 地址（见 4.4）。

### 4.2 放行防火墙

Windows 防火墙默认会拦掉设备发起的入站连接，这一步通常被忽略。
**以管理员身份**打开 PowerShell，添加放行规则：

```powershell
New-NetFirewallRule -DisplayName "SmartLight MQTT" -Direction Inbound `
    -Protocol TCP -LocalPort 1883,8083 -Action Allow -Profile Any
```

> 若之前已给 `node.exe` 放行（出站/入站均已允许），这一步可跳过。

### 4.3 首次配网（BLE）

设备出厂不带 WiFi 凭据时，第一次上电会自动开 BLE 广播，等手机把 WiFi 名称和密码发过来。

**App 用 ESP BLE Prov**（应用商店搜 `ESP BLE Prov` 或 `ESP-IDF Provisioning`）。

> 选 App 时可以留意一下：本工程用的是 `wifi_prov_scheme_ble`
> （protocomm BLE / GATT server），与 EspBlufi 所用的 BluFi 协议不是同一套，
> 用 EspBlufi 会扫不到设备。

如果这是第一次接触配网，也可以先试试把 WiFi 凭据写进固件
（`CONFIG_WIFI_STA_SSID`，见工程根目录 README），跑通联网之后再回来体验配网。

| 步骤 | 应该看到什么 |
|------|--------------|
| 1. 给设备上电 | 串口：`尚未配网，进入蓝牙配网模式` + 设备名 `PROV_LIGHT_xxxx` |
| 2. App → 扫描 | 列表里出现 `PROV_LIGHT_xxxx` |
| 3. 点进去，填 POP | POP = `abcd1234`（menuconfig → `BLE 配网` 可改） |
| 4. 选 WiFi、填密码 → 下发 | 串口：`收到 WiFi 凭据: SSID=...` |
| 5. 配网成功 | `配网成功，已连上 AP` → `配网流程结束，正在重启以应用新配置` |
| 6. 自动重启后 | `检测到已保存的配网凭据: xxx` → `已连接 WiFi: xxx, IP: 192.168.x.x` |

**凭据存在哪：** NVS 分区。`WIFI_STORAGE_FLASH` 模式下配网凭据会落盘，
掉电、只重烧应用（不擦全片）都还在，所以**只会配一次**。

**想换 WiFi 重新配：**

- 串口敲 `WIFI RESET` → 设备 3 秒后自动重启并重新广播
- 或烧录时先擦全片（工程根目录的 `flash_ble_prov.cmd` 就是这么做的）

> 一个容易忽略的小细节：`CONFIG_WIFI_STA_SSID` 填了值时，设备会直接连这个网络、
> 不再开广播，看起来像是配网没生效。想演示配网的话，把它留空、
> 并确认 NVS 里没有旧凭据就可以了。

## 五、主题（Topic）约定

设备 ID 默认为 MAC 尾号（例如 `light_7B7544`）。

| 方向 | Topic | 报文示例 |
|------|-------|----------|
| 设备 → 平台 | `light/<id>/telemetry` | `{"temp":28.0,"light":45,"mode":1,"r":0,"g":153,"b":19,"ts":...,"timer":{...},"alarms":[...]}` |
| 设备 → 平台 | `light/<id>/state` | `{"mode":1,"r":0,"g":153,"b":19}` |
| 设备 → 平台 | `light/<id>/status` | `online` / `offline`（LWT 遗嘱，retained） |
| 平台 → 设备 | `light/<id>/set` | `{"mode":1}` 或 `{"r":255,"g":128,"b":0}` 或 `"ON"` / `"OFF"` |

`mode` 取值：**0 = 关闭，1 = 自动，2 = 手动**。

大屏按钮发出的报文：

| 按钮 | 报文 |
|------|------|
| 自动 | `{"mode":1}` |
| 手动 | `{"mode":2}` |
| 关灯 | `{"mode":0}` |
| 发送颜色 | `{"r":R,"g":G,"b":B}`（设备收到后自动切到手动模式） |
| 启用定时 | `{"cmd":"timer","action":"set","hour_on":22,"minute_on":0,"hour_off":6,"minute_off":0,"week":[1,2,3,4,5]}` |
| 关闭定时 | `{"cmd":"timer","action":"off"}` |
| 添加闹钟 | `{"cmd":"alarm","action":"add","hour":7,"minute":30,"repeat":"daily","week":[1,3,5]}` |
| 删除闹钟 | `{"cmd":"alarm","action":"del","slot":2}` |
| 清空闹钟 | `{"cmd":"alarm","action":"clear"}` |
| 响铃测试 | `{"cmd":"alarm","action":"test"}` |

### 定时 / 闹钟的报文约定

**上报方向**（跟着每条 telemetry 一起发，页面据此渲染控件）：

```json
{
  "temp": 26.8, "light": 46, "mode": 1, "r": 255, "g": 140, "b": 0,
  "timer":  { "enable": 1, "on": "22:00", "off": "06:00", "week": [1,2,3,4,5] },
  "alarms": [ { "slot": 1, "hour": 7, "minute": 30, "repeat": "daily", "week": [1,3,5] } ]
}
```

- `week` 是 **1~7 的数组（1 = 周一 … 7 = 周日）**，与串口命令一致；
  空数组 `[]` 表示「每天」。
- `timer.enable`：1 = 定时生效、0 = 已关闭。
- `alarms[].repeat`：`daily`（重复，可配合 week）/ `once`（响一次后自动删除）。
- 设备端最多 **3 个闹钟**，槽位号 `slot` 由设备分配（1~3），删除时要带这个号。

**下发方向**：

| 指令 | 说明 |
|------|------|
| `{"cmd":"timer","action":"set","hour_on":22,"minute_on":0,"hour_off":6,"minute_off":0,"week":[...]}` | 设置定时开关灯，`week` 可省略（省略则保留原星期）；开灯时间晚于关灯即为**跨天** |
| `{"cmd":"timer","action":"week","week":[6,7]}` | 只改星期 |
| `{"cmd":"timer","action":"off"}` | 关闭定时 |
| `{"cmd":"alarm","action":"add","hour":7,"minute":30,"repeat":"daily","week":[1,3,5]}` | 添加闹钟，`repeat` 省略按 `daily` |
| `{"cmd":"alarm","action":"del","slot":2}` | 删除指定槽位 |
| `{"cmd":"alarm","action":"clear"}` | 删除全部（等价 `delall`） |
| `{"cmd":"alarm","action":"test"}` | 立即响铃 10 秒，不依赖校时，用于验证蜂鸣器 |

> 指令处理完设备会**立刻补发一条遥测**，大屏上的列表随即刷新 —— 不需要刷新页面。
> 同理，从串口 `ALARM ADD` / `TIMER ON` 改的配置也会主动上报，两端始终一致。

> 到点触发需要联网校时（SNTP），设备时间还没同步时闹钟与定时器不会动作，
> `action:"test"` 的响铃则随时可用。

### 关于在线状态

`light/<id>/status` 是 retained 消息，设备重启瞬间的 `offline` 遗嘱会一直保留，
新开的页面会立刻收到。因此**判断设备是否在线不能只看 status**，
应以"是否在持续上报遥测"为准 —— 大屏就是这样实现的。

## 六、OTA 远程升级

升级用的 HTTP 服务由已经跑起来的 `broker.js` 提供，不需要额外的云厂商或控制台。

### 6.1 原理

```
[电脑] broker.js 的 8083 端口
   ├── /ota/<name>.bin   固件静态下载
   └── /api/ota          列出 ota 目录里有哪些固件
            ▲
            │ ① MQTT 下发 {"cmd":"ota","url":"http://<电脑IP>:8083/ota/xxx.bin"}
            │ ② 设备用 HTTP GET 拉取固件
            │
[ESP32] components/cloud_ota
   ├── esp_https_ota_begin / perform / finish（带百分比进度）
   ├── 校验镜像自描述（project_name / version，防止拉错文件）
   └── 写入备用分区 → 设置下次启动分区 → 重启
            ↓
   新固件启动 → main.c 的 confirm_ota_image() 标记有效（取消自动回滚）
```

**双分区 + 回滚保护**：`partitions.csv` 里 `ota_0` / `ota_1` 各 4 MB。
新固件永远写进"当前没在跑"的那个分区，**校验不过就不切换，设备继续跑旧固件 —— 不会变砖**。

### 6.2 版本号在哪改

根目录 `CMakeLists.txt`：

```cmake
set(PROJECT_VER "1.1.0")
```

改这个值 → 重新编译 → 版本号写进镜像，设备 OTA 时会打印出来，
用来确认"确实升上去了"。

### 6.3 操作步骤

**第一步：把新固件发布到服务器目录**

```cmd
host\push-firmware.cmd
```

它会把 `build\smart_light.bin` 复制到 `host\ota\smart_light.bin`。

**第二步：确认 broker.js 在跑**（新增 `/ota` 路由后需要重启才生效）

**第三步：触发升级（三选一）**

| 方式 | 操作 | 适用场景 |
|------|------|----------|
| 串口 | 敲 `OTA` | 调试期最快 |
| 串口指定地址 | `OTA http://192.168.1.100:8083/ota/smart_light.bin` | 换服务器 / 换文件名 |
| 大屏 | 页面「OTA 固件升级」→「推送到设备」 | 演示用，无需敲命令 |

**第四步：看日志**

```
smart_light: OTA 就绪  当前固件 v1.0.0  运行分区 ota_0
cloud_ota: ========== OTA 升级开始 ==========
cloud_ota:   当前版本  : 1.0.0     运行分区: ota_0
cloud_ota:   服务器固件: smart_light  v1.1.0  编译于 ...
cloud_ota:   固件大小  : ... 字节
cloud_ota:   下载中  10%   (...)     ← 每 10% 打印一次
cloud_ota:   ✔ OTA 成功：新固件已写入备用分区，重启后生效
cloud_ota:   5 秒后自动重启进入新固件…
```

重启之后：

```
cloud_ota: 运行分区: ota_1
smart_light: OTA 就绪  当前固件 v1.1.0
```

> **看到「运行分区 ota_0 → ota_1」且「版本 v1.0.0 → v1.1.0」，OTA 就算验证成功。**

### 6.4 失败会怎样

| 情况 | 设备行为 |
|------|----------|
| 服务器没开 / 网址写错 | 打印"连接固件服务器失败"，继续跑旧固件 |
| 传输中断 | 打印"下载中断"，**不切换分区** |
| 固件被截断 | 打印"固件数据不完整"，**不切换分区** |
| 写入 / 校验失败 | **不切换分区**，旧固件照常运行 |
| 新固件启动后没确认 | bootloader 自动回滚到旧固件 |

## 七、常见问题

**Q：Broker 窗口报「TCP 1883 已被占用」**
A：有别的 MQTT 服务在跑。换端口启动：

```cmd
set MQTT_PORT=1884 && set WEB_PORT=8084 && node broker.js
```

**Q：大屏一直显示「等待数据…」**
A：1) 确认 Broker 窗口在跑；2) 点右上角「模拟设备」先验证链路；
3) 看 F12 控制台有没有连接报错；4) 确认页面订阅的是 `light/+/telemetry`。

**Q：设备日志里 MQTT 连不上**
A：按顺序排查：① 设备与电脑是否同网段（`ping` 一下）② 防火墙规则加了没
③ Broker 地址里的 IP 是不是最新的 ④ Broker 是否在监听（`netstat -ano | findstr 1883`）。

**Q：想换成公共 Broker 快速验证**
A：把 `CONFIG_CLOUD_MQTT_URI` 改成 `mqtt://broker.emqx.io:1883`，
大屏右上角地址框填 `wss://broker.emqx.io:8084/mqtt`。
